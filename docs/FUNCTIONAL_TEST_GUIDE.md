> 适用对象：完全不了解本项目的测试人员。
> 目标：对照本文档，在浏览器中**逐个、完整**地完成网站所有功能点的手动测试。
> 项目代号：SciReAgent（科研试剂知识图谱与采购平台，站点标题 "LabPro Global"）。
> 文档版本：2026-07-11 初版。

## 0. 怎么用这份文档

1. 先按 **第 1 章** 把环境跑起来，拿到"前端地址"（形如 `http://localhost:5173`）。
2. 用 **第 1.6 节** 的测试账号登录对应角色。
3. 按 **第 3 章** 的功能清单逐条测试。每条用例包含：
   - **页面**：要打开的网址（相对路径，拼在"前端地址"后面）。
   - **前置条件**：需要什么角色登录、需要什么数据。
   - **操作步骤**：照着点。
   - **预期结果**：看到什么算通过。
   - **优先级 / 备注**：P0=必测核心；P1=重要；P2=增强。备注里标注已知限制。
4. 每条用例在 **第 6 章** 的表格里记 `通过 / 失败 / 阻塞`，失败要附截图与现象。
5. 跑完一轮后，按 **第 4 章** 的端到端场景把关键链路串起来复测。

约定：本文所有路径都以"前端地址"为基准。例如"打开 `/products`"即访问 `http://localhost:5173/products`（端口以你实际拿到的为准）。

## 1. 测试环境准备

### 1.1 前置软件
- **Node.js** 18+（建议 22.x）
- **Python** 3.12（后端用）
- **Git**
- 一个现代浏览器（Chrome / Edge / Firefox 均可）
- 操作系统：Windows / macOS / Linux 均可

### 1.2 获取代码
代码在本机工作区内（由项目负责人提供路径）。前端在 `src_claude/frontend`，后端在 `src_claude/backend`。如无代码，先 `git clone` 项目并 `cd` 到项目根目录。

### 1.3 启动后端（必须先启动）
```bash
cd <项目根>/src_claude/backend
DB_ENGINE=sqlite venv/Scripts/python.exe manage.py runserver 127.0.0.1:8000
```
- Windows 上若 `venv` 不存在，先由负责人初始化（见项目说明）。
- 启动成功标志：终端输出 `Starting development server at http://127.0.0.1:8000/` 且**无报错**。
- 后端必须运行在 **8000 端口**，前端通过代理访问它。

### 1.4 启动前端
```bash
cd <项目根>/src_claude/frontend
npm install          # 仅首次需要（安装依赖）
npm run dev
```
- 启动后终端会打印一行 `  ➜  Local:   http://localhost:5173/`（端口被占用时会自动换成 5174 / 5175 等，**记下实际地址**）。
- **测试一律通过这个前端地址访问**，不要直接访问 8000（前端 API 走代理）。

### 1.5 验证环境可用
1. 浏览器打开前端地址，应看到首页（Hero 大图 + 导航栏）。
2. 打开 `/products`，应看到产品列表（非空白、非报错页）。
3. 若首页白屏或列表报错，先检查后端是否真的在 8000 运行（见 1.3）。

### 1.6 测试账号（已核实可用）

| 角色 | 用户名 | 密码 | 权限说明 |
|------|--------|------|----------|
| 游客（匿名） | 不需要登录 | — | 仅能访问公开页面 |
| 客户（customer） | `e2e_customer` | `E2ePass123!` | 注册用户，`is_staff=False`；可用购物车/结算/我的订单/PO 客户侧 |
| 管理员 / 研究员（staff） | `admin` | `admin123` | `is_staff=True`；额外可进 `/workspace` 研究后台与 `/admin/*` 管理台 |

> 若密码与当前环境不符，以项目负责人提供为准，**不要自行改库**。
> 测试时建议用浏览器"无痕窗口"或每次清 localStorage，避免旧登录态干扰。

### 1.7 全局交互识别指南（看不懂界面时看这里）
本项目**几乎不用第三方组件库**，交互都是原生实现的，识别方式如下：
- **按钮**：普通带文字的按钮；主按钮为 emerald（绿）实心、次按钮为描边或 amber（琥珀）实心。
- **购物车角标**：右上角购物车图标上会叠加一个小数字（红底白字），表示购物车商品总件数（同一商品加多次会累加）。
- **弹窗 / 对话框**：不是浏览器原生弹窗的那种"大白板"，而是页面中间浮起的卡片（背后有半透明遮罩）。关闭方式：点"取消/关闭"按钮，或点遮罩空白处。
- **Toast 提示条**：页面角落（通常右上或顶部）短暂弹出的深色小条，显示"成功/失败"文案，几秒后自动消失。
- **原生 alert / confirm**：浏览器自带的弹窗（PO 提交、地址删除、订单操作等处使用），点"确定/取消"即可。
- **分页**：列表底部有一排页码/上下页按钮（组件名为 DataPagination），点页码切换。
- **排序**：列表表格的某些列标题可点击（鼠标移上去有手势），点一次升序、再点降序。
- **加载态**：数据加载时页面会出现转圈或局部变灰，加载完恢复，属正常现象，等它结束再操作。

### 1.8 已知限制（测试中遇到"失败"但属于预期，记录即可，不必当 bug 提）
- **地址簿保存**（`/po/addresses` 新增/保存地址）：后端接口尚未上线，保存会弹出错误提示。属已知限制。
- **遗留页面** `products/ProductEditPage`、`admin/AdminProductsPage`、`admin/AdminProductEdit`：当前导航中已不可直达，产品管理统一走 `/workspace/products`。见第 5 章。
- **AI 工具类按钮**（部分管理页内的 enrich / validate / recommend 等）：调用外部 AI 服务，在本地环境可能较慢或需网络，点按时耐心等待，超时/报错记为"环境依赖"而非功能缺陷。

## 2. 角色与权限总览

| 页面类型 | 游客 | 客户(customer) | 管理员(staff) |
|----------|------|----------------|---------------|
| 公开页（`/`、`/products`、`/search`、`/quote-request` 等） | 可访问 | 可访问 | 可访问 |
| 登录/注册页（`/login`、`/register`） | 可访问 | 已登录会被自动跳走 | 已登录会被自动跳走 |
| 需登录页（`/settings`、`/checkout`、`/orders`、`/po/*`） | 自动跳到 `/login?redirect=原路径` | 可访问 | 可访问 |
| 需管理员页（`/workspace/*`、`/admin/*`） | 自动跳到 `/login?redirect=原路径` | 自动跳回首页 `/` | 可访问 |

> 测试权限时，重点验证：**游客访问受限页被拦、客户访问管理员页被拦、管理员畅通**。

## 3. 功能测试清单

优先级：**[P0]** 核心必测　**[P1]** 重要　**[P2]** 增强

### A. 公开浏览与导航

#### A-01 首页加载与导航　[P0]
- 页面：`/`
- 前置：游客
- 步骤：
  1. 打开首页。
  2. 查看顶部导航栏（分类标签、Logo、Sign In / 购物车）。
  3. 点击某个分类标签（如 Products / Applications）。
  4. 点击 Hero 区的搜索框，输入关键词回车。
- 预期：
  - 首页正常显示，无白屏、无报错。
  - 导航栏元素可见；点击分类跳到对应列表页。
  - 搜索回车后跳到 `/search` 并显示结果。

#### A-02 全局搜索　[P0]
- 页面：`/search`
- 前置：游客
- 步骤：
  1. 在任意页顶部搜索框输入一个已知词（如 `buffer` 或产品名片段），回车。
  2. 查看结果列表；点击某条结果。
- 预期：结果列表展示匹配项；点击跳到对应详情页。空关键词时显示空态或提示，不崩溃。

#### A-03 应用列表与详情　[P0]
- 页面：`/applications` 及 `/applications/:id`
- 步骤：
  1. 打开 `/applications`，使用搜索框过滤、翻页。
  2. 点击某条进入详情 `/applications/:id`。
  3. 在详情页点击关联的"方法 / 产品"链接。
- 预期：列表可搜索、可翻页；详情展示字段；关联链接可跳转。

#### A-04 方法列表与详情　[P0]
- 页面：`/methods` 及 `/methods/:id`
- 步骤：同 A-03（把路径换成 methods）。注意列表有分类过滤 chips，点 chips 过滤。
- 预期：过滤 chips 生效；详情可跳关联协议/产品。

#### A-05 协议列表与详情　[P0]
- 页面：`/protocols` 及 `/protocols/:id`
- 步骤：
  1. 打开 `/protocols`，用过滤 chips + 搜索 + 翻页。
  2. 进详情，查看可排序的步骤表（点列标题排序）。
- 预期：列表过滤/搜索/分页正常；详情步骤表列可点击排序，顺序随点击切换。

#### A-06 产品列表与详情　[P0]
- 页面：`/products` 及 `/products/:id`
- 步骤：
  1. 打开 `/products`，用分类 pills、搜索、翻页。
  2. 进详情 `/products/:id`。
  3. 调整"数量"输入框数值。
  4. 点击 **Add to Cart**。
- 预期：
  - 列表分类/搜索/分页正常。
  - 详情显示产品信息、SKU 行、文档链接、相关应用/协议标签页。
  - 点 Add to Cart 后：右上角购物车图标上的角标数字 +数量；页面弹出成功提示条（"Added to cart" 类文案）；点购物车图标跳到 `/cart`。
  - 同一产品多次加购，角标数字累加。

#### A-07 研究目标列表与详情　[P0]
- 页面：`/research-goals` 及 `/research-goals/:id`
- 步骤：同 A-03（路径换 research-goals）。列表可用状态下拉 + 搜索过滤。
- 预期：过滤/搜索/分页正常；详情可跳关联。

#### A-08 404 页面　[P0]
- 页面：`/随便一个不存在的路径`
- 步骤：地址栏输入不存在路径回车。
- 预期：显示 404 提示页，有"返回首页"按钮；点击回到 `/`。

### B. 账户与认证

#### B-01 注册（多步表单）　[P0]
- 页面：`/register`
- 前置：游客
- 步骤：
  1. 打开 `/register`，按 3 步填写必填字段（邮箱、密码、组织等约 12 项）。
  2. 每步点"下一步"，必填项留空时点"提交"看校验。
  3. 最后一步提交。
- 预期：
  - 必填项为空时给出错误提示，不能前进。
  - 提交成功后显示成功横幅（success banner）；账户创建后可凭该账号登录。
  - （测试用新账号建议起容易识别的用户名，避免污染；如不需长期保留可忽略。）

#### B-02 登录　[P0]
- 页面：`/login`
- 前置：游客
- 步骤：
  1. 用 `e2e_customer / E2ePass123!` 登录。
  2. 用错误密码登录一次。
- 预期：
  - 正确凭据 → 进入首页或 `redirect` 回跳的目标页；右上角显示用户名/头像 + 购物车。
  - 错误密码 → 页面显示错误条幅，仍停留在登录页。
  - 已登录状态下再访问 `/login` 会被自动跳走（见 B-04）。

#### B-03 登出　[P0]
- 页面：任意已登录页
- 前置：客户或管理员已登录
- 步骤：点击右上角用户菜单中的"登出 / Sign out"。
- 预期：回到游客态（导航变 Sign In），再访问需登录页会被拦回 `/login`。

#### B-04 已登录访问 guest 页重定向　[P1]
- 步骤：以客户登录后，地址栏直接打开 `/login` 和 `/register`。
- 预期：被自动跳回首页 `/`（或工作台，视角色），不显示登录表单（避免回环）。

#### B-05 账户设置　[P1]
- 页面：`/settings`
- 前置：已登录（任意角色）
- 步骤：修改部分字段（如昵称/联系方式），点"保存"。
- 预期：页面显示保存成功横幅；刷新后修改仍生效（部分字段可能只读，依界面为准）。

### C. 购物车 / 结算 / 我的订单

#### C-01 购物车查看与改数量　[P1]
- 页面：`/cart`
- 前置：已加购至少 1 件商品（先按 A-06 加购）
- 步骤：
  1. 打开 `/cart`。
  2. 修改某商品数量输入框，失焦/确认。
  3. 点"删除"某商品。
  4. 观察右上角购物车角标。
- 预期：数量修改生效、小计更新；删除后该商品消失、角标数字同步减少；删除时有成功提示条。

#### C-02 购物车去结算　[P1]
- 页面：`/cart`
- 步骤：点"去结算 / Checkout"按钮。
- 预期：跳转到 `/checkout`（未登录会被拦到 `/login`，见 B-02 先登录）。

#### C-03 结算下单　[P1]
- 页面：`/checkout`
- 前置：已登录客户 + 购物车有商品
- 步骤：
  1. 填写收货/账单等字段（约 12 项），必填留空时尝试提交看校验。
  2. 提交订单。
- 预期：
  - 必填校验生效（留空不能提交，有提示）。
  - 提交成功后生成订单，跳到订单详情或订单列表；`/orders` 里出现该新订单。

#### C-04 我的订单列表与详情　[P1]
- 页面：`/orders` 及 `/orders/:id`
- 前置：已登录客户
- 步骤：
  1. 打开 `/orders`，翻页查看。
  2. 点某订单进详情，查看状态时间线。
- 预期：列表展示当前用户自己的订单；详情展示订单项、状态、时间线；非本人订单不应出现。

### D. 询价申请

#### D-01 提交询价（匿名也可）　[P1]
- 页面：`/quote-request`
- 前置：游客即可（无需登录）
- 步骤：
  1. 填写多字段表单（产品、数量、联系方式等约 11 项）。
  2. 必填留空时提交，看校验。
  3. 正确填写后提交。
- 预期：必填校验生效；提交后显示成功提示/横幅。

### E. PO 采购门户（客户侧，需登录客户）

#### E-01 提交采购单（PO）　[P1]
- 页面：`/po/submit`
- 前置：已登录客户
- 步骤：
  1. 点"添加行项目"，填写 PO 号、行项目（产品/数量/单价等，动态多行）。
  2. PO 号或行项目留空时点提交，看校验（浏览器 alert）。
  3. 填全后提交。
- 预期：动态增删行项目可用；校验弹 alert 提示；提交成功后出现成功提示，PO 进入"已提交"状态，可在 `/po/orders` 看到。

#### E-02 我的采购单列表与详情　[P1]
- 页面：`/po/orders` 及 `/po/orders/:id`
- 前置：已登录客户
- 步骤：
  1. 打开 `/po/orders`，翻页。
  2. 点某 PO 进详情，查看状态时间线、发票、发货、附件等信息。
- 预期：列出当前客户自己的 PO；详情展示完整流转信息与状态标签。

#### E-03 地址簿　[P1]
- 页面：`/po/addresses`
- 前置：已登录客户
- 步骤：
  1. 点"新增地址"，填写字段，保存。
  2. 尝试编辑、删除（删除会弹 confirm 确认）。
- 预期：
  - 表单弹层可打开/关闭。
  - **已知限制**：保存很可能返回错误提示（后端接口未上线）。遇到错误提示记为"已知限制"，不要当 bug。
  - 删除有确认框。

#### E-04 重新下单　[P2]
- 页面：`/po/reorder`
- 前置：已登录客户 + 有历史 PO
- 步骤：打开页面，选择历史 PO 执行重订操作。
- 预期：能基于历史 PO 复制行项目并生成新采购单草稿/提交（依界面引导）。

#### E-05 下载中心　[P2]
- 页面：`/po/downloads`
- 前置：已登录客户
- 步骤：打开页面，点击某文档的下载链接。
- 预期：能列出可下载文档；点击触发下载或打开文件。

### F. PO 采购门户（内部台，需管理员）

> 以下页面仅 `admin` 账号可进；用客户账号访问会被拦回首页（验证见 F-06）。

#### F-01 订单审核台　[P1]
- 页面：`/admin/po/review`
- 前置：管理员已登录
- 步骤：
  1. 打开审核台，查看待审 PO 列表（可分页）。
  2. 对某 PO 执行"通过 / 驳回 / 指派负责人"等审核动作。
- 预期：列表展示待审 PO；审核动作后该 PO 状态变化（如变为已确认），列表相应更新。

#### F-02 发货台　[P1]
- 页面：`/admin/po/shipments`
- 前置：管理员已登录
- 步骤：
  1. 打开发货台，选择待发货 PO。
  2. 创建发货记录（可多批发），填写发货字段（运单号等）。
  3. 标记"已发货 / 已签收"。
- 预期：发货记录可创建；状态随"已发货→已签收"推进；时间线更新。

#### F-03 开票台　[P1]
- 页面：`/admin/po/invoicing`
- 前置：管理员已登录（针对"已签收 DELIVERED"状态的 PO）
- 步骤：选择已签收 PO，填写开票字段，开票。
- 预期：仅对已达可开票状态的 PO 可开票；开票后状态推进，客户侧 `/po/orders` 详情可见发票信息。

#### F-04 AR 账龄报表　[P2]
- 页面：`/admin/po/ar`

## 4. 端到端业务链路场景（串测）

### 场景 1：游客加购 → 结算下单 → 查看订单　[P0]
1. 游客打开 `/products/31`（或任意产品），加购 2 件 → 角标显示 2。
2. 点购物车图标 → `/cart` → 去结算 → 被拦到登录。
3. 用 `e2e_customer` 登录后回到结算。
4. 填收货信息提交 → 跳订单详情。
5. 打开 `/orders` 确认出现该订单，详情状态时间线正确。

### 场景 2：PO 全流程（客户提交 → 管理员审核 → 发货 → 开票 → AR）　[P1]
1. 客户登录 → `/po/submit` 提交一张采购单（填 PO 号 + 行项目）→ 出现在 `/po/orders`（状态：已提交）。
2. 管理员登录 → `/admin/po/review` 审核通过（状态推进）。
3. 管理员 → `/admin/po/shipments` 创建发货、标记已签收（状态：已签收）。
4. 管理员 → `/admin/po/invoicing` 对该 PO 开票（状态：已开票）。
5. 管理员 → `/admin/po/ar` 报表中应体现该 PO 应收。
6. 客户 → `/po/orders/:id` 详情可见发票与发货信息。

### 场景 3：研究员维护知识图谱　[P1]
1. 管理员登录 → `/workspace/goals` 新建一个研究目标。
2. `/workspace/applications` 新建应用并关联到该目标。
3. `/workspace/methods` 新建方法关联到应用。
4. `/workspace/protocols` 新建协议关联到方法。
5. `/workspace/products` 新建产品，关联到方法/协议。
6. 回到公开页 `/research-goals`、`/applications` 等，确认新建的实体可见、关联跳转正确。

## 5. 已知限制 / 暂不可测项（汇总）

| 项 | 现象 | 处理 |
|----|------|------|
| 地址簿保存 | `/po/addresses` 保存地址返回错误提示 | 后端接口未上线，记为已知限制 |
| 遗留编辑页 | `products/ProductEditPage`、`admin/AdminProductsPage`、`admin/AdminProductEdit` 在导航中不可直达 | 产品管理统一测 `/workspace/products`，不单独测这些 |
| AI 工具按钮 | 管理页内 enrich/validate/recommend 调用外部 AI，可能慢/超时 | 环境依赖，非功能缺陷；记录现象即可 |
| 部分状态数据 | PO 八态、订单旧态需特定种子数据才能全展示 | 默认库可能只有部分状态；遇空态记录，不必强求 |

## 附录 C：术语表
- **PO**：Purchase Order，采购订单。客户在 `/po/submit` 提交，经审核/发货/开票流转。
- **SKU**：产品的具体规格条目，产品详情页中可有多行 SKU。
- **Toast**：页面角落弹出的短暂提示条。
- **dialog-overlay**：页面中间浮起、带遮罩的自定义弹窗（非浏览器原生 alert）。
- **Workspace**：管理员用的研究后台（`/workspace`），用于维护知识图谱实体与产品。
- **Staff / 管理员**：`is_staff=True` 的账号（本项目即 `admin`），可进所有后台。
- **Customer / 客户**：普通登录用户（`is_staff=False`），可用购物与 PO 客户侧，不能进后台。
