# docs/legacy/ — 已冻结的历史文档

> ⚠️ **这个目录里的东西不要再照着写代码。**

这里存放的是项目**设计期（2026-06 及更早）**的产物，已被现行实现取代。

## 为什么整目录搬走

原来的问题是：`docs/legacy/00_MASTER_INDEX.md`（搬移前位于 `docs/` 根目录）虽然**文件内第二行**就写了 `DEPRECATED`，
但文件名看起来是全项目最权威的样子。新人或 AI 按文件名找文档，
**一定先打开它**，然后读到一份 4 个月前的设计。

⇒ 现在把"废弃"这件事**放在路径上**，不依赖任何人在文件内部找注释。

## 目录内容

| 路径 | 内容 | 时间 |
|---|---|---|
| `00_MASTER_INDEX.md` ~ `12_DESIGN_SYSTEM.md`（13 篇） | 初始设计草案（产品愿景/架构/领域模型/PRD/API spec/路线图…） | 2026-06-27 |
| `specifications/`（17 篇） | 发布期规格（架构原则/信息架构/非目标…） | 2026-06-14 |

## 它们还有价值吗

**有，但不是当规范用。** 唯一价值是**记录当时的意图**：

- 项目 git 历史从 **2026-07-10** 才开始（首个提交是 477 文件 / 96464 行的 squash），
  6 月设计期**没有 git 历史**
- 所以这 30 篇是**当时"为什么这么设计"的唯一记录**
- ⚠️ 例如 `is_featured → display_priority` 的改动理由，在整个仓库里
  **只剩这里和 `PHASE1_TDD_TEST_PLAN.md` 的碎片** —— 不要删除，也不要"按现状重写"，
  那会用"可再生的现状"换掉"不可再生的意图"
