# 反方审计意见书：Product ↔ Protocol 相关性设计稿

> **审计立场**：反方 = 数据科学审计视角 + 化学试剂领域专家视角。
> **审计对象**：`docs/product-protocol-relevance-design.md` + 配套探针 `apps/bridges/management/commands/probe_protocol_relevance_v3.py` + 抓取 `crawl_bioz_jena.py`（均为 2026-08-05 终态）。
> **审计方法**：逐条核对设计稿声明与探针/抓取代码的实际行为，对"先跑"阶段得出的结论做独立压力测试。
> **结论**：**暂不同意签字**。设计稿方向（全量保留 + 相关排序 + 折叠）整体可取，但存在 **1 个 Blocker 级事实错误、2 处设计稿内部事实不一致、以及 6 项必须在落地前回答的方法论缺陷**。其中 Blocker 直接推翻"Bioz 为并列强信号"的核心卖点。

## 一、Blocker：Bioz 信号在代码里是"产品级先验"，并非"协议级证据"（推翻核心卖点）

**设计稿声称**（§1 第 40 行、§4 第 120 行算法框）：
> `evidence_count` = 与协议语料重叠的 Bioz 文献数；Bioz 是"产品 SKU 级第三方文献，证明此具体货号被用来做 X"，与 docx 同为强信号。

**代码实际行为**（探针 `probe_protocol_relevance_v3.py`）：
- 第 241–243 行：`bioz_vendor, jcat = resolve_jena_cat(prod)`；`bioz = bioz_cached_count(bioz_vendor, jcat)`；`bioz_boost = min(1.0, bioz/5.0)` —— **这三者都在"每个产品"粒度算一次**，在协议循环之外。
- 第 255 行：`score = WD * dom + WB * bioz_boost` —— **同一 `bioz_boost` 被加到该产品的每一条协议上**。
- `bioz_cached_count` 返回的是该 jena 货号下 Bioz 文献的**总条数**（第 128–141 行），**没有任何一步把文献标题/摘要与该协议做重叠匹配**。

**后果（反方判定）**：
1. SC8065（`bioz=7`）的 +0.15 抬升，**会均等地加到它的"RNA-seq 协议""Western blot 协议""克隆协议"等所有协议上**，哪怕那 7 篇 Bioz 文献全是关于 RNA-seq、与 Western blot 毫无关系。
2. 设计稿 §2.2 给 `ProductProtocol` 设了 `relevance_basis="bioz"` 字段，且 §4 第 123 行 `basis = ... "bioz" if ev else ...`。按此实现，**一个产品的每一条协议只要该产品有 Bioz，就都会被盖上 `bioz` 戳**——即便该协议与那些文献无关。这与铁律②（"最强相关性 = 最能匹配产品的数据"）直接矛盾：你把产品级的存在性证据，冒充成了协议级的匹配证据。
3. 因此设计稿反复强调的"Bioz 为并列强信号、对少数产品真实抬升排名"（§4 第 132–136 行、§1 第 25 行、§11 待确认项）**在语义上是错的**：抬升是真实的，但抬升的是"产品整体权重"，不是"某条协议的相关性"。所谓"SC8065 因 Bioz 跃居 #1"，严格说是"SC8065 的所有协议都因 Bioz 被整体抬高"。

**反方要求（must-fix，Blocker）**：在把 Bioz 标为协议级 `relevance_basis` 之前，必须先做**文献↔协议的对齐**（用文献标题/摘要与协议领域词或 method 名做重叠，或至少用文献中的技术关键词）。否则 `evidence_count` 与 `relevance_basis="bioz"` 是误导字段，违反铁律②的"透明/准确"。若短期内做不了对齐，则必须诚实降级：Bioz 只能作为**产品级置信先验**（影响"该产品整体值得多看一眼"），不得写入逐协议的 `relevance_basis`，UI 徽标也不能对无关协议打"文献支持"。

## 二、设计稿内部事实不一致（须先修正，否则评审基础失真）

| # | 位置 | 问题 |
|---|---|---|
| C1 | §1 表格第 36 行："Bioz 仅 jena 命中产品（**77/106**）" | 与 §6（第 158 行"复跑命中 **61**"）矛盾。77 是 `match_jena` 原始命中数，61 是去掉 16 个无可用厂商货号后的真实可抓数。表格与 §9 第 3 步"跑完 77"均为过期数字。 |
| C2 | §4 第 129 行权重标注 `domain=0.85 / bioz=0.15` | 与同节算法框第 118 行 `score = 0.5*coverage + 0.5*precision` 是**两层不同的加权**（外层 0.85/0.15 是 dom vs boost 的混合；内层 0.5/0.5 是 coverage vs precision 的 F 内部）。稿子把两者混谈，读者会误以为"0.85/0.15 是相关性总权重"。 |
| C3 | §4 算法框第 120 行 `ev = bioz_cached_count(protocol.catalog_anchor)` | 代码里 `protocol` 并无 `catalog_anchor` 属性；实际是产品级 `resolve_jena_cat(prod)`。伪代码暗示"逐协议 Bioz"，与真实"逐产品 Bioz"相反（见 Blocker 一）。 |

**反方要求**：C1/C3 是事实错误，必须在签字前改写；C2 需把两层加权显式拆开写明。

## 三、数据专家视角：方法论缺陷（6 项）

### D1. 阈值 H=0.40 / M=0.20 是"看直方图顺眼"挑的，无 ground truth
§4 第 138 行、§5 第 150 行、§11 第 3 项都称阈值"v3 终态 grid 实测锁定"。但 grid 只报告"每档可见协议数分布 / fb（跌兜底产品数）"，**没有任何标注相关性**。选 H=0.40 只因为"fb=40 看起来合理"。这是**循环论证**：用 F-score 定义相关性，又用"想显示几条"反推阈值。
**反方要求**：抽 30–50 个产品，请试剂科学家对候选协议标"相关/不相关"，算 precision@5、recall@10、NDCG，再据此定 H/M。否则阈值只是装饰数。

### D2. 35 词领域词表是"同源语料里手挑的小词典"，覆盖与泛化都不足
- **覆盖缺口（化学/蛋白域尤甚）**：RNA/DNA 试剂应用远不止 35 类。缺失明显者：cloning / ligation / restriction digestion / phosphorylation / conjugation / crosslinking / Southern/Northern/dot blot / EMSA / Co-IP / pull-down / ELISA / immunohistochemistry / immunofluorescence / flow cytometry·FACS / single-cell(scRNA-seq, droplet) / spatial transcriptomics / ribosome profiling / metabolic labeling(PRO-seq,GRO-seq) / 5'·3' RACE / RNA structure(SHAPE) / isothermal amplification(LAMP) / SNP genotyping / CRISPR screening / mRNA vaccine 等。词表对**蛋白试剂应用**几乎空白——而这是试剂大盘的重要一块。
- **选择偏差**：词表从"125 docx + 现有协议"里长出来，当然在自己身上"有效"。对**未见过的产品描述 / 新同义词**会失效（如 docx 写"cDNA preparation"未被 `reverse transcription` 收入；写"RT"未被收录）。
**反方要求**：(a) 扩充并**外部化**词表；(b) 用一份系统从未见过的试剂目录做召回测试；(c) 至少跑一个 embedding 基线（usage + protocol 文本过 sentence-transformers 算余弦）作为对照，证明 F-score 方案优于/不劣于朴素基线。

### D3. F-score 套在"领域词集合"上，丢失了特异性
`score = 0.5*coverage + 0.5*precision`（第 109–118 行）。例：产品 P={dna,rna}，协议 Q={dna,rna,crispr,sequencing} → F=0.5·(2/2)+0.5·(2/4)=0.75；而另一个**更泛**的协议 Q'={dna,rna,nucleotide,oligo,labeling} → F=0.5·1+0.5·(2/5)=0.70。两者几乎一样高，但前者是"该试剂正好用于 CRISPR+测序"，后者是"沾边"。**F-score 把"恰好对上具体技术"和"同处一个大领域"压成了相近分数**。对试剂↔协议，特异性（precision 的语义）比覆盖更重要，0.5/0.5 配重不当。

### D4. 探针只评估"已有桥的产品"，79%≈0 的口径被误读
探针第 219–230 行：`if not method_ids: continue` / `if not proto_ids: continue`。所以"106 产品 / 2501 对"是**已有 MethodProtocol 桥的子集**，不是全量产品。设计稿 §10 第 200 行把"79% 对 score=0"说成"笛卡尔积噪声，验证铁律②需折叠"——**这是误标**：大量零分是**正确的不相关**（DNA 连接酶本就与 RNA-seq 无关），不是噪声。框架成"噪声"会诱使团队过度折叠、低估真负例的价值。

### D5. docx 用途抽取的质量完全未测量
设计稿称"125/125 含用途句"（§2.1、§7），但这只是 `load_docx_usage` 能取到非空串。没说明：`usage` 是全文摘要、是精选句、还是正则乱抓？若是厂商营销长文本（见化学视角 K1），`extract_domains` 是在噪声上匹配。**零精度/召回评估**。
**反方要求**：人工审 10 个 docx，定义"用途"到底是什么、抽取准确率多少，写入设计稿风险节。

### D6. Bioz 权重 0.15、封顶 5 条、featured 兜底 0.25，全是 magic number
- 第 243 行 `boost = min(1, bioz/5)`、第 122 行 `score += 0.15*boost`、第 254 行 `dom==0 and edit → 0.25`：**无任何依据**。
- 更关键：Bioz 仅对 ~12/106 产品非零（§4 第 136 行）。对 94/106 它恒为 0。把它叫"**并列**强信号"严重夸大——它是**稀疏、非对称**的增强器，不是与 docx 并列的信号。

## 四、化学试剂专家视角：领域正确性缺陷

### K1. 厂商自述（docx 用途）是营销文案，不宜做"主信号"
docx 用途陈述是厂商产品描述/blurb，常写"for sensitive detection""high quality""for research use"——**模糊、非精确实验技术**。把"厂商自述"定为**主信号（100% 覆盖、最强）**风险高。反方立场：试剂的**应用笔记 / 被引协议**才是更准的用途信号；Bioz（真实文献引该货号做 X）在"真实性"上**应高于**厂商自述。设计稿把二者定为"并列"，反而弱化了更可信的 Bioz。建议层级应为 **Bioz（实证典型用法）> docx（厂商声称能力）**，而非并列。

### K2. 化学身份 / 同义 / 化合物类别未进入相关性，只用于 jena 链接
CAS 仅用于 `match_jena` 链接（第 34、148 行），**不参与打分**。后果：
- 同一化合物（同 CAS）不同命名的两个产品，可能得到不同相关性分。
- **修饰类型特异性丢失**：5-mC、假尿苷(ψ)、2'-O-Me、硫代磷酸酯等修饰核苷酸，适用协议与未修饰 NTP 完全不同（如 ψ→mRNA 疫苗/表观转录组；2'-O-Me→反义/siRNA）。词表把"nucleotide"泛化，抓不到修饰类别差异。
- **立体/异构特异性丢失**：dNTP vs ddNTP、2'-F vs 2'-O-Me、对映体，应用相反。词表无此维度，可能把产品匹配到"用错异构体会失败"的协议。

### K3. 无单一 CAS 的试剂（试剂盒/酶/缓冲液/预混液）会错链 Bioz
`match_jena` 对无 CAS 者回退 name/synonym（第 153–159 行）。不同厂家的"Reverse Transcriptase"虽同名但 CAT# 不同、酶也可能不同；name 回退可能链到 jena 的另一个酶 → **错误的 Bioz 锚点 → 错误的文献证据**（叠加 Blocker 一的"产品级均摊"，错误被放大到所有协议）。

### K4. 协议相关本是"方法定义"的，方法本体缺口 = 覆盖缺口
试剂通过"它实现的方法"相关于协议。但 `MethodProtocol` 是固定桥。若某 docx 用途描述的应用（如"用于 5' RACE"）系统里没有任何 Method 覆盖，它**无法桥到任何协议**——覆盖缺口。系统 Method 本体是否覆盖全部真实试剂应用，设计稿未论证。

### K5. 全局阈值 H=0.40 对"窄用途"试剂过严
对试剂，**一个正确技术匹配往往就是全部意义**（如 Cy3-dUTP 就是为荧光标记）。H=0.40 可能把"唯一正确的那条协议"也折掉。§5 说 MIN_VISIBLE=5 用 featured 补足——但补的是**编辑精选（可能不相关）**，反而可能淹没那条低分但唯一正确的协议。
**反方要求**：至少保证"若产品存在 ≥1 条领域词命中的协议，则强制展示其 top-1，不受 H 截断"；H 应改为**每产品自适应**而非全局常数。

### K6. "相关性"概念本身混淆了两种维度
设计稿把"厂商声称可用于 X"（能力/capability，来自 docx）与"文献实证常用于 X"（典型性/typicality，来自 Bioz）**直接相加成一个标量**。这是范畴错误：二者是不同的相关维度。
**反方要求**：至少在 UI 上**分轴呈现**——"厂商称可用于" vs "文献实证常用于"——而不是合成一个分数让用户以为"0.787 就是最相关"。这同时呼应铁律②的"透明"。

## 五、对"两条铁律"的张力审计

- **铁律①（全量保留）vs 铁律②（折叠低相关）**：DB 不删是对的，但**折叠是发现层的删除**。若研究者不点"显示全部(M)"，折叠协议永不可见。MIN_VISIBLE=5 的兜底用 featured 填充，可能把"编辑精选但不相关"摆在"低分但真相关"之前（K5）。张力未真正化解，只是移到 UI。
- **featured 可覆盖计算分**：第 251–254 行，编辑精选且 dom=0 → 给 0.25。这是"人肉覆盖算法"的口子，是 feature 也是信任风险。设计稿已用档位隔离（featured 档最低），处理尚可，但 0.25 仍是 magic number，且可能让两条 featured 协议内部乱序。

## 七、反方结语

方向（全量保留 + 相关排序 + 折叠非删）我**同意**，两铁律的定调也**同意**。但当前稿子在"Bioz 信号"这一核心卖点上存在 **Blocker 级事实错误**（产品级均摊冒充协议级证据），且阈值、词表、docx 抽取、化学特异性四大处均无验证、无依据。按"先讨论后落地"的纪律，**现在落地会把一个尚未被验证、且部分错误的相关性模型写进生产**。

建议路径：先把 B1/C1–C3 改掉；同时补 D1 标注集与 D2 基线（这俩不贵，却能决定 H/M 与词表是否站得住）；K1/K6 的"分轴呈现"可在 UI 层低成本兑现，建议一并做。其余（K2/K3/K5 的化学特征深化）可作第二阶段，但不应在第一版就声称"Bioz 为并列强信号"。

—— 反方（数据专家 ∩ 化学试剂专家），2026-08-05
