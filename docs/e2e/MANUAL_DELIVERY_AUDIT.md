## 5. 交付时必须一并告知的 3 条边界（不可省）

> 这三条不是"以后再说"，而是**读这份文档的人必须知道的前提**。已写进正文，此处再强调。

### 边界 1：生产是内部测试态，不是上线态
生产**全站挂 nginx Basic 认证**（`realm="SciReAgent Internal Test"`，实测 10/10 路径 401）。
**没有凭据的人连首页都打不开**。因此：
- 任何对外汇报只能说「**开发测试态 + 种子数据**」
- 我们做的 sitemap / SEO 优化**对搜索引擎当前无效**（爬虫也吃 401）
- 生产数据现状：公开产品 **0**（125 全在回收站）/ 库存 **0** / 订单 16 / COA 33 / SDS 12

### 边界 2：账号自救能力为零
**改密码是假成功**（弹"feature will be available soon"但无任何后端调用）+ **全站无忘记密码**
+ **登录页重发验证按钮是死链** ⇒ 用户忘记密码 = 永久锁死，只能运维上 Django admin 重置。
一线应答口径必须是"走工单"，**不能说"点那个按钮"**。

### 边界 3：浏览器实测的覆盖面是"关键事实"而非"逐页像素"
- **52/52 页**都有浏览器**加载级**验证（`check_browser_coverage.py` 实测）
  —— 本轮为此专门补了 `manual-pages-smoke.spec.cjs`（此前 15 页未跑过，其中含 `/po/orders/:id` 与两个收敛类页）
- 但"加载级"≠"逐元素交互"：断言的是"渲染出正文 + 未被踢走 + 无未捕获异常"，
  **不等于每个按钮都点过**
- **没有像素级视觉回归**（仓库无基线截图机制）

> 补测过程中我自己的测试也有过两个假通过，已修正并记录在下方「审计自身的两个坑」：
> ① 收敛类 id 取成 `null` ⇒ `/applications/classes/null` 也被算"渲染成功"
> ② 客户页 `/orders/:id` 用 staff 身份测 ⇒ 测的不是"客户看自己的单"
> 修正后：收敛类用真实 `ap_k011`/`rg_k170`，客户用自己的订单 `1257`，两个上下文分开。

⇒ 所以：**"这个按钮叫什么、在哪个位置"这类描述，详情页部分请以实际页面为准**；
凡涉及"能不能做 / 会不会 403"的结论，都有实测支撑。

## 8. 审计自身的两个坑（防止下次重犯）

| # | 坑 | 现象 | 教训 |
|---|---|---|---|
| 1 | **动态 id 取成 null 也算通过** | 收敛类 id 从错的 JSON 路径取，得到 `null`；`/applications/classes/null` 仍渲染出 200+ 字符 ⇒ 判"成功"，**实际测的是 404 页** | 断言里必须**显式校验 id 非空**（`expect(ids.cls_ap).toBeTruthy()`），不能只看页面长度 |
| 2 | **用错身份测客户页** | 用 staff 打开 `/orders/:id`，命中的是全库订单而非"我的订单"，语义不对 | 一个页面属于哪个角色，就用**那个角色**的上下文测；跨角色页要分上下文 |

另有一条**流程性教训**：脚本用 `python - <<'PYEOF'` 写内联代码时，
**heredoc 会吞掉正则里的反斜杠**（`\s` → `s`），导致 `re.findall` 静默返回空列表、断言全过。
本项目已踩 **4 次** ⇒ 凡带反斜杠的 Python，一律写成 `.py` 文件再跑。
