## 0. 结论速览

> **强制度**列说明：**硬性** = 机构采购中不做就会卡住流程；**常见** = 多数场景需要，缺了会被客户质疑；**条件性** = 特定条件下才成为硬性。

| # | 行业惯例 | 强制度 | 本项目设计 | 判定 |
|---|---|---|---|---|
| 1 | 先 Quote 后 PO 是机构采购的**常见路径**（标准品可直下单） | 常见 | 承认该习惯（PRD:34），但 Quote→PO 仅列 **P1**、`Order.quote` **可空**（ARCH:188） | 🟡 增强 |
| 2 | 「无 PO 不发货 / 无 PO 不付款」，发票必带 PO 号 | **硬性** | `Order.po_number` + ARCH **R4 加 unique** | ✅ |

| 4 | bill-to / ship-to **分离** | **硬性** | ARCH **R8 新建 `Address` 表**（`type=BILLING/SHIPPING`） | ✅ |
| 5 | grant / 基金号标记 | 常见（**联邦资金下硬性**） | `Order.grant_code`（ARCH:184） | ✅ |
| 6 | 新供应商注册（供应商向机构报 W-9 / ACH） | **硬性（但属线下流程）** | 属线下；PRD:14 已声明「供应商向大学注册」为**不构建范围** | ✅ 合理 |
| 7 | Net30 为默认账期，Net45/60 面向大客户 | 常见 | NET30 默认 + 开票台可选 Net30/Net45 | ✅ |
| 8 | 30/60/90 账龄 + 分级催收 + **部分付款核销** | 硬性（账龄/催收）· **常见（部分付款）** | 账龄 ✅ 催款（到期前 7 天 / 超期 30 天）✅ **部分付款仅列 P2** | 🟡 **必要** |

| 10 | 冷链 / 干冰 / 危险品按 **UN 编号 + IATA/DOT** | 条件性（**卖危险品时硬性**） | 冷链 ✅ 干冰（运输方式）✅ **hazmat / UN 编号未建模** | 🟡 条件性 |

## 2. 硬缺口详述：免税（Sales Tax Exemption）

### 2.1 行业事实

- **美国公立高校依法免缴州 / 地方销售税**，且通常要求「必须用 University PO / P-Card 采购并直接付款给卖方」才可享受；供应商若索要凭证，机构提供**州免税证明**即可（如 Arizona Form 5000「研究用化学品 / 研发设备」专项免税证书、Rochester 免税号 125542 / NYS 免税证书）。（事实）
- **供应商侧义务**：**须接受免税证书并免收销售税**。主流平台印证：**VWR / Avantor 明确规定「Guest Profile 不享有 tax exempt 资格」**，开立账户时须提供免税号 —— 说明免税资格与**账户 / 机构**绑定。（事实）

### 2.2 本项目现状（v1.1 已独立核验）

- 独立核验：`tax` 关键词在 **PRD 仅出现 2 次**（`PRD.md:218` 与 `PRD.md:220`，均为 `subtotal/tax_total/grand_total` 字段列表）；在 **ARCHITECTURE 出现 0 次**。
- ⇒ **结论：字段在、规则无** —— 没有任何免税状态判定、没有任何"置 `tax_total=0`"的路径。（事实）

### 2.3 风险（★ v1.1 已标注推断）

- 美国大学客户在结账 / 付款环节看到含税金额时，**可能拒付税款或整单挂起**，需要人工介入对账。
  ⚠️ **（推断）** —— 该后果由「高校免税（事实）+ 供应商须免收税（事实）」推导得出，**本次未取得客户实际拒付行为的直接证据**；但即便只作为"高风险可能性"，也足以支撑把免税列为 P0（因为补它的成本远低于人工对账成本）。

### 2.4 建议补法（最小改动）

| 项 | 内容 |
|---|---|
| 数据 | `Organization.tax_exempt_id`（免税号，可空） |
| 逻辑 | 提交 PO / 开票时按机构免税状态置 `tax_total = 0` |
| 票据 | Invoice PDF 上标注 `Tax Exempt ID`（行业惯例做法） |
| 优先级 | **P0** —— 见 §5.1 决策点 D1 |

## 3. 部分符合项详述

> 本节 4 条均按 §1.3 的双档口径标注（必要 / 增强 / 条件性）。

### 3.1 Quote → PO 未成为默认路径 🟡 增强

**行业事实**：机构 / 竞争性采购普遍把「询价」作为流程第 1 步、PO 作为获批后步骤（如 Victoria University 采购程序明确 Step1 询价 → Step3 PO；Rochester 大学规定交易额超过阈值须先取竞争性报价）。**但对标准目录品，授权账户在线直接下单亦被广泛接受**，报价可「按需」而非强制。（事实）

**本项目现状**：PRD 角色 A 故事 2（PRD:34）明确描述「先生成 Quote，确认价格后再关联 Quote 号提交 PO」这一**客户习惯**；但 **P1-2 才把它列为 P1**（PRD:66），且 `Order.quote` 设计为**可空**（ARCH:188），PRD P0-2 提交流程（PRD:60）亦未要求 Quote 必填。

**判定：🟡 增强** —— **不强制是符合行业的**（标准品可直下单），但建议在客户端 UI 上把「请求报价」与「用 PO 结账」做**并列一等公民**，而非埋在 P1。

### 3.2 部分付款分级过低 🟡 **必要**

**行业事实**：收到部分款时应「**先核销、余额保持 open、记录短付原因**」，而非默认按最旧发票冲抵；这是 AR 的标准实务。（事实）

**本项目现状**：AR Aging 30/60/90 ✅（P1-4）、分级催款 ✅（到期前 7 天 / 超期 30 天，PRD:200），但**部分付款核销列为 P2**（PRD:45 / PRD:72 / PRD:190）。

**判定：🟡 必要** —— `PaymentRecord` 多笔天然支持部分付款（PRD:221），**建议把 `Invoice.balance_due` 的定案从 P2 提到 P1**；注意 ARCH §8.2 #3 尚待拍板「存储字段 vs 派生属性」。

### 3.3 hazmat / UN 编号未建模 🟡 条件性

**行业事实**：干冰 = **UN1845**（Class 9，空运须符合 IATA PI954，**包装必须透气**）；液氮 = UN1977；感染性物质 Category B = UN3373。危险品须按 DOT / IATA / IMDG 分类、标签、申报。（事实）

**本项目现状**：运输方式含 `Ambient / Cold Pack / Dry Ice / Blue Ice`（PRD:111）、`DRY_ICE`（ARCH:185）、冷链温度记录（P2）；但 **hazmat 分类与 UN 编号未建模**。

**判定：🟡 条件性** —— **仅当所售试剂含危险品时**为硬需求。建议补 `SKU.hazmat_class` + `SKU.un_number`，并在发货单 / Packing List 上打印运输合规提示。

### 3.4 账户价 / 合同价缺失 🟡 增强

**行业事实**：主流平台（Thermo Fisher、Sigma-Aldrich / Merck、VWR）均为「**未登录仅显示目录价，登录后显示账户 / 合同价**」，且实时库存与 lead time 也需登录可见。（事实）

**本项目现状**：有实时库存徽标与 lead time（PRD:33 / PRD:89）、reorder（P2）、PO + 信用卡双支付 ✅；但**只有 `SKU.price` 目录价**，未见机构级 / 合同价概念（批量折扣阶梯也被延后到 P2，ARCH:637）。

**判定：🟡 增强** —— 对大学大客户，**合同价 vs 目录价是常态**；建议 P1 补机构级价格，或先在 UI 明确标注「合同价待议」。
