# 任务说明 · PCR 判定（42 条）

> 本包**自包含**：判定所需的东西都在包里，**不需要查库、不需要问人**。
> 包内三份：本说明、`pcr_kappa_samples_42.json`（42 条样本）、`pcr_kappa_definition_v0.1_诸葛亮_reviewed_曹操.yaml`（判定依据的定义）。
> 提交用 `pcr_kappa_output_template.jsonl`。

---

## 一、你要做什么

对这 **42 条协议**，逐条判断：**它是否按这份定义属于「PCR」这个方法**，给出三档结论之一、写一句理由，并在适用时指明它落在哪条排除项上。

**判据只有一份**：包内的定义文件（`version 0.1`，作者诸葛亮、复核曹操）。
不要用自己的常识替代定义里写的 `must` / `on_topic_requires` / `exclude`。

---

## 二、三档怎么判

| 结论 | 条件 |
|---|---|
| **`wrong`** | 定义的 `must` **没有全部满足** |
| **`on_topic`** | `must` **全部**满足，**且** `on_topic_requires` 也满足 |
| **`tangential`** | `must` 全部满足，但**产出不是本方法本身的产出** |

> `wrong` **只能**由 `must` 不满足产生。**不要**因为"产出不对"就判 `wrong` —— 那是 `tangential`。

---

## 三、证据只认两处

1. 该条的 `objective`（目标陈述）；
2. 该条给出的**前 6 步**步骤正文（字段 `steps`，每条 `text` 是"步骤标题 + 正文"）。

两处**同等有效，任一处陈述即可**。
**仅 `protocol_name` 出现"PCR""qPCR"等字样，不构成证据** —— 名字只是上下文，不能据此下判断。

### `objective` 为空时

本批有 **5 条** `objective` 为空（`objective_len = 0`）。**空 ≠ 方法没执行**，只表示"没有目标证据"：

- 空，但**前 6 步**陈述了方法证据 → **按步骤正常判**；
- 空，且前 6 步**也**无方法证据 → **拿不准往低判** → 判 `wrong`，并在 `why` 里写明
  **`insufficient detail`** 这个短语。

**不得**因为"没写目标"就判 `wrong`。

## 四、提交格式

文件 `pcr_kappa_output_template.jsonl`，**每行一条**，保持 `bridge_id` 原样，把三个空字段填上：

```json
{"bridge_id": 12093, "verdict": "on_topic", "why": "...", "exclude_item": ""}
```

| 字段 | 取值 |
|---|---|
| `bridge_id` | **照抄包里的值，不要改、不要漏行** |
| `verdict` | `on_topic` / `tangential` / `wrong` 三者之一 |
| `why` | **英文**，一到两句，写清依据（引到具体是哪一步/哪句更好） |
| `exclude_item` | 判 `tangential` 或 `wrong` 且因某条 `exclude` 时，填 `E1`…`E5`；否则留空 |

**必须 42 行，`bridge_id` 与包里一一对应。**

## 五、几条纪律

1. **不要查数据库、不要搜原文、不要问人** —— 包里的文本就是全部依据。
2. **不要用查看器粗略浏览长文本**：本批最长 `objective` **52,875 字符**（仅 1 条），其余 ≤ 3,042 字符；
   最长 `steps` 合计 **7,661 字符**。时间主要花在那一条超长记录上，其余很快。
3. **不要改动样本文件**，也不要试图从 `bridge_id` 反查 —— 编号只是对账用的。
4. 判不准就按"往低判"处理并在 `why` 里说明，**不要猜**。
